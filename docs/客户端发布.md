# Daocaijing 客户端发布

Daocaijing 使用同一套 React 前端，分别套上 Capacitor（Android）和 Electron（Windows/macOS）。客户端内置前端资源，登录、行情和 AI 请求走 `https://daocaijing.com`；后端不需要随安装包分发。

## 本地构建

```bash
# 桌面开发（需要另行启动后端时，可先 npm run backend:long）
npm run desktop-dev

# macOS 安装包（在 macOS 上执行）
npm run desktop:pack:mac

# Windows 安装包（在 Windows 上执行；也可在已配置 Wine 的 macOS/Linux 上尝试）
npm run desktop:pack:win

# Android 调试 APK
npm run android:debug

# Android 发布 APK（需要 android/keystore.properties）
DAOCJING_ANDROID_VERSION_CODE=42 DAOCJING_ANDROID_VERSION_NAME=1.2.0 npm run android:release

# Google Play 发布 AAB（需要 android/keystore.properties）
DAOCJING_ANDROID_VERSION_CODE=42 DAOCJING_ANDROID_VERSION_NAME=1.2.0 npm run android:aab
```

产物位置：Electron 在 `dist/`，Android 调试 APK 在 `android/app/build/outputs/apk/debug/`，发布产物在 `android/app/build/outputs/apk/release/`。

仓库里的 `Build Daocaijing Desktop` 工作流会在打 `v*` 标签或手动触发时，分别在 macOS 和 Windows runner 上生成安装包并上传为 Actions artifact。

## 发布前检查

- Android 发布签名放在本机 `android/keystore/` 和 `android/keystore.properties`，不要提交到 Git；发布任务缺少签名会直接失败。签名文件必须备份，否则旧用户无法升级。
- 当前 Android target/compile SDK 为 API 36。正式发布前必须递增 `DAOCJING_ANDROID_VERSION_CODE`，并确认包名 `com.daocaijing.app` 与商店应用身份一致。
- GitHub Actions 的 `Daocaijing Android release` 工作流只响应 `v*` 标签，使用 `ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD` 和 `FCM_GOOGLE_SERVICES_JSON` secrets 生成签名 AAB/APK；缺少任一项会直接失败。
- macOS 分发到其他设备前需要 Apple Developer 签名与公证；Windows 分发前建议配置代码签名证书，避免 SmartScreen 警告。
- Android 发布脚本默认把前端资源内置进 APK，API 走 `https://daocaijing.com`；联调线上网页时才显式设置 `CAPACITOR_SERVER_URL`。不要把远程网页模式当作正式包的唯一资源来源。
