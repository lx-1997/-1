# DeepFocus 生产上线核对清单

> 目标：把平台从"演示态/沙箱受限"切到机构生产态。
> 本清单聚焦 **#2 出网 + 真实数据**（运维/部署层，非代码），并附 **#1 认证**（已实现）和 **#3 召回投递**（已实现）的开关与配置。
> 验收口径：`GET /api/system/readiness` 分数 ≥ 85、`status=ready`，无 blocker。

---

## 0. 一句话背景

代码层的"优雅降级"已经做得很到位（外网失败返回结构化 warnings 而非崩溃）。当前演示态拿不到实时数据，**主因不是代码，而是两件运维事**：
1. **出网被代理封**：沙箱 `HTTPS_PROXY=10.9.0.31:8838` 对云模型/行情/公告等域名返回 403。
2. **没有配置生产数据源 key / 凭据**。

把这两件解决，绝大多数 live 路径会自动恢复——代码已经写好等着。

---

## 1. 出网（egress）— #2 核心

沙箱出网走代理且**选择性封锁**：google/github 可达，eastmoney / sina / tencent / stooq / 巨潮 / nasdaq / api.minimaxi.com 等多被 403。代码里已对**模型域名**加了 `NO_PROXY` 绕过（`model_config.py: configure_data_source_egress()`），行情/公告类同理需要放行。

- [ ] **确认生产网络出站策略**：生产机能否直连公网？还是必须走企业代理？
- [ ] **若走代理**：把以下域名加入代理 allowlist（或在应用侧 `NO_PROXY` 直连绕过）：
  - 模型：`api.minimaxi.com`、`api.openai.com`（或自建兼容网关域名）
  - 行情：`finnhub.io`、`www.alphavantage.co`、`*.eastmoney.com`、`push2.eastmoney.com`、`push2his.eastmoney.com`、`stooq.com`、`query1.finance.yahoo.com`、`www.google.com`（/finance）
  - 公告/财报：`*.eastmoney.com`、`np-*.eastmoney.com`、`*.sse.com.cn`、`*.szse.cn`、`www.cninfo.com.cn`（巨潮）、`api.nasdaq.com`
  - 新闻：`news.google.com`、央视来源域名
- [ ] **校验 NO_PROXY 生效**：`configure_data_source_egress()` 在 lifespan 启动时跑；确认生产 env 没有更高优先级的 `HTTP(S)_PROXY` 覆盖它。
- [ ] **逐域名连通性冒烟**（生产机上）：对上面每个域名 `curl -I` 确认非 403/超时。
- [ ] **DNS / 防火墙**：确认上述域名解析正常、出站端口 443 放行。

> 验收：`/api/market/quotes?symbols=AAPL` 返回 live 价（非种子兜底）、`/api/system/readiness` 的 `market_data` 检查转 pass。

## 4. 认证 / RBAC / 存储（#1，已实现）

代码已就绪，上线只需翻开关 + 配密钥。详见 `backend/.env.example`。

- [ ] `DEEPFOCUS_AUTH_REQUIRED=true`（开启全局强制鉴权）
- [ ] `DEEPFOCUS_JWT_SECRET=<高熵随机串>`（**必须**，否则用不安全开发默认并告警）
- [ ] `DEEPFOCUS_JWT_TTL_MINUTES`（默认 720）
- [ ] 预置管理员：`DEEPFOCUS_ADMIN_EMAIL` + `DEEPFOCUS_ADMIN_PASSWORD`（首启自动建 admin）
- [ ] 机构部署建议关自助注册：`DEEPFOCUS_ALLOW_SELF_REGISTER=false`
- [ ] **存储切托管库**：`DEEPFOCUS_DATABASE_URL=postgresql+psycopg://user:pass@host/db`
  - 认证子系统直接跑在该库上；存量 10 个 raw-sqlite 模块为后续增量迁移项（见下）。

> 验收：readiness `auth` 检查 pass（需 auth_required 且已有账号）、`storage` 检查随托管库转 pass。

## 5. 信号召回投递 + 回流度量（#3，已实现）

未配置时优雅降级为 `skipped`，绝不出网。配齐后真实投递并可度量回流。

- [ ] 邮件（SMTP）：`DEEPFOCUS_SMTP_HOST/PORT/USER/PASSWORD/FROM/TLS`
- [ ] Web Push（VAPID）：`DEEPFOCUS_VAPID_PRIVATE_KEY` + `DEEPFOCUS_VAPID_SUBJECT`，并 `pip install pywebpush`
- [ ] 回流追踪基址：`DEEPFOCUS_PUBLIC_BASE_URL`（后端公开地址）、`DEEPFOCUS_APP_BASE_URL`（前端地址）
- [ ] 验收闭环：订阅 → 推一条信号 → 收到邮件/推送 → 点链接 → `GET /api/realtime/recall/metrics` 的 `delivered/clicked/click_through_rate` 增长，前端"信号流→回流度量"出现数字。

## 6. CORS / 安全边界

- [ ] `CORS_ORIGINS` 设为明确前端域名，**不要**用 `*`（readiness `cors` 检查 fail on `*`）
- [ ] 高风险 MCP server 必须 `approval_required=true`（人工确认）+ allow-list + 调用审计
- [ ] 所有 secret 走密钥管理（不进 git、不进镜像层），`.env` 仅本地
- [ ] HTTPS / 反向代理终止 TLS；后端不直接对公网裸跑
