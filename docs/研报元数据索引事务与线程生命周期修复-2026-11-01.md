# 研报元数据索引事务与线程生命周期修复

范围为内部研究平台，商业级质量目标不等于已达标。本轮修复研报元数据入库，没有修改策略、成本、暂停规则、原实验或样本外门槛，没有部署、调用真实供应商或开户。

## 已确认的问题与修复

上一轮保留的 `unresolved-index-probe.json` 显示：合成来源正常返回一条研报，但索引调用为零，`org` 未定义被宽泛异常捕获吞掉。因此“列表可读”不能证明分类索引存在。旧证据继续保留，不回写成成功。

列表规范化后使用独立 `research_wire_index`：机构名取规范字段或默认值，记录实际观察时钟，元数据标注不伪装全文。准备与 SQLite 写入均由真实工作线程执行，事件循环继续响应；最多一个索引工作、500条、原字段累计1MiB、标注载荷2MiB，SQLite忙等待2秒、合作式工作预算5秒。预算并非操作系统硬实时保证。

一批对象、标签和实体关系在一个数据事务提交；中途异常、时限或类型冲突回滚，提交后才登记内存成功ID。已有同类记录整条保留，元数据不能覆盖已解读全文或审核信息。初始化DDL在数据事务前，数据失败可能留下空表结构；不宣称DDL与数据整体原子。

取消等待者后，名额由真实线程直到退出持有；没有可被全局任务取消提前终止的中间Task。线程执行Future被保护并排空，调用者仍收到取消；取消期间已提交的元数据可能保留。提交失败/忙碌返回内部pending状态，下次真实刷新可重试；这不是持久化outbox，也不承诺所有发现的研报必然已索引，公共响应模型未必暴露内部indexing字段。
