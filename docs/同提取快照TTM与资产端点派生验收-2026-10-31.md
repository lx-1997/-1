# 同一补充提取快照的TTM与资产端点派生验收

2026-10-31，内部研究离线能力。新增独立quant_financial_fact_derived与CLI ttm/ttm-assets子命令，不改原财报/补充事实入库层、原始清单或恢复v6代码；派生算法的来源身份单独返回，不把旧档案重标为新来源。

## 一个数据快照和一个知识时点

一个owner指定一个补充提取快照ID，在单一只读SQLite事务中验证完整提取链、原回执指纹/账户和原文，然后完成全部部件选择与算术。所有部件使用同一as_of和mode，不能拼接两个补充快照。TTM只接受声明的YTD流量；中期采用当前YTD+上年全年−上年同期，年末仅该全年。先按知识时点选择每一期间最新披露，再读取新指标；新版缺项、撤回、空白或缺报均保留不可用，不回退旧公告或其他提取版本，不补零。

as_recorded同时受父回执与补充提取的实际入库次日边界约束。边界前不执行派生函数，ttm_value、endpoint_average_assets及整个嵌套result都为NULL。无效期间、类型、端点、身份、未来时钟等仍拒绝，不以“尚不可见”掩盖非法请求。historical_reconstruction明确是晚采集事实重建已见历史。

## 资产端点必须明示，精度跨JSON保留

ttm-assets必须分别指定起点、终点资产所来自的报表期间和列。系统先检查该列指向的资产日期恰好等于流量起始日前一天及流量终止日；读到事实后再次验证存量类型和日期。当前期末、上年度末及上年度末调整后列不能随意替代。两端仍按同一知识时点选各自报表的最新修订，不假定两个端点在经济上已认证可比。

端点简单平均不是日均或季均资产。运算采用整数分；均值保留三位元字符串和约分后的有理数。JSON的numerator和denominator也用十进制字符串，避免JavaScript安全整数上限引起丢失。对新未发布实现实际复现过：整数分子199999999999999999999被浮点JSON消费端变成2e+20，随后改为字符串并保留失败日志。极值均值999999999999999999.995仍精确保留；半分钱不预先四舍五入成分。

组合请求任何必需部件缺失时，不输出部分派生值。原始已可见部件可在result中审查缺项原因；门禁前result整体为空。端点全为0可以报告精确均值0及positive_for_possible_future_denominator=false，不做除法。没有应计比率、分数、排序或策略信号，所有PIT/会计可比性/策略/晋级/商业资格标记仍false。

## 可复现命令

```sh
python3 scripts/quant-financial-facts.py --db /absolute/research.sqlite3 --owner OWNER ttm-assets \
  --id TYPED_PACKET_ID --issuer-id cninfo:9900002009 --symbol 002109 \
  --period-end 2025-03-31 --metric consolidated_net_profit \
  --as-of 2026-05-01T00:00:00+08:00 --mode historical_reconstruction \
  --begin-report-period-end 2024-03-31 --begin-column current_period \
  --end-report-period-end 2025-03-31 --end-column current_period
```

只计算TTM时用ttm并不传端点参数。CLI返回0仅表示算术可用，2表示所求组合缺失/空白/时点不可用，1表示无效或非所属账户请求；既有put/review行为保持。
