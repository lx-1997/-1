# 研究任务终态与隔离测试验收 · 2026-10-30

范围为内部研究平台的旧 quant_jobs 路径，独立于 quant_research_store 的持久实验。没有改变策略、历史数据、费用、风控或晋级门槛，没有部署或执行实盘。

## 先复现，再修复

新增隔离回归在修复前实际得到4失败、5通过：另一进程注册表取消后，旧计算的进度和完成可以重新覆盖取消；启动恢复写入的 worker_interrupted 也能被覆盖；NaN 可以存成成功；提供商异常中的模拟凭证 canary 原文进入公开错误。失败日志保留在 artifacts/quant-job-reliability-20261030/before.log，canary 为测试常量而非真实凭证。

另发现 test_quant_jobs 的异步清理夹具在严格模式被忽略，且未指定临时库。先同时修复夹具声明、临时数据库和独立任务注册表，再运行反例，避免激活清理后触及本机研究库。持久化测试也隔离注册表；完成测试直接等待任务，不靠固定睡眠猜时序。

## 最终行为

- 创建显式 INSERT，配额检查和插入在同一 BEGIN IMMEDIATE 事务中；已有任务仅可在同 owner 且数据库仍为 pending/running 时更新，不再 upsert。
- 完成、失败、取消为不可覆盖终态；迟到回调发现终态即退出，删除后的旧任务也不能复活。不同进程取消无需共享内存。启动恢复仍明确依赖单 API worker，不宣称已实现分布式调度或跨机器租约。
- 完成结果严格 JSON 序列化，拒绝非有限数；异常转安全失败码 research_failed，清空结果，不公开上游响应。序列化与数据库保存发生在成功发布之前。
- SQLite 连接显式关闭；原结果读取、owner 隔离、启动中断、启动前取消和现有一小时任务保留策略不变。此临时任务表不替代不可变研究证据库。

16项定向用例通过，包括真实独立 Python 进程取消、无后续进度时的迟到完成、三类终态不可覆盖、错 owner、删除不复活、队列容量、错误脱敏和旧持久化兼容。没有用线上或本机真实账户数据制造故障。

完整相关回归429项通过，剩余7条旧代码/LibreSSL/SWIG警告；被忽略的异步夹具警告已消失。精确源码树记录保存在同一 artifacts 目录。本修复只证明这些任务生命周期边界，不证明硬超时能立即杀死任意计算线程、完整灾备、生产发布或策略盈利能力。策略两组原失败结论保持，商业级整体目标仍未完成。
