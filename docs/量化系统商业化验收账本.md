3. 先验证数据与收益基准，再另立新的研究协议；旧数据均已见，不把修正后的开发结果重新标为全新 OOS。上一份协议的“没有合格候选”结果保留。

## 2026-10-30 继续推进：分红现金与 FIFO 税务账簿

新增 `quant_dividend_book.py`，从独立初始账簿开始接收成交、现金权益和交易日，不以覆盖历史净值的方式处理分红。旧研究源文件和源码指纹保持不变。

- 明确选用 `cn_resident_individual_public_a_share` 情景，不推定用户身份；机构、港股通及其他税制不在此版本支持范围。
- 登记日收盘固定分配权，除息确认为应收，按付款日收盘入现金的保守模拟时点处理；未到账权益不能用于买入。税务按取得时间 FIFO 匹配，月/年界限按自然月（年），含周年当日。登记在 2015-09-08 之后才使用 2015-101 规则。
- 卖出时形成应纳税负债，下一交易日按研究模型扣款；实际券商现金扣收时点仍需交割单验证。保留已付现金、未付税款和未实现分红税预留，买入不能花掉已预留税款。
- 分笔卖出按每个权益事件的累计精确税额再按分计量，防止拆单重复取整；该取整模型尚待实际清算账单核对，不宣称等同所有券商。
- 支持 JSON 持久化恢复、逐日幂等、失败时原账簿不被修改；不同知识可用模式、不同源文件版本、已登记事件修订不能悄悄混用。日频模型拒绝同日同证券反向交易，以免把逐笔 FIFO 冒充完整日终净额税务。
- 不能跳过交易日、登记快照或非交易日支付，非交易日不能注入新收盘价格；没有报价不能默认为零。税制资料目前核验至 2026-10-30，超出覆盖范围拒绝推定未来规则。政策证据后续更新与冻结账户兼容迁移仍待完善。

用两组真实封存成交实际逐日核验，每组 535 个 OOS 交易日，金额均对到账簿：事后重建情景下第一组抽样权益仍为 0，第二组税前支付 8100 元、应纳和已付税款均为 1620 元。按当时系统实存信息模式，两组本次补采事件均不入账；这只说明数据可用模式，不意味着经济上无分红。汇总 `quant-dividend-tax-book-audit-20261030.json`，详细日志与状态 `artifacts/quant-tax-book-20261030/`。

## 2026-10-30 继续推进：事件参与实际交易与风险决策

按用户本轮澄清，继续建设商业级内部研究系统；没有降低任何策略收益或风险晋级门槛。

新增开发内核 `quant_event_replay.py`，不是对旧收益加回现金。每个交易日先做开盘前税款/应收与原始开盘估值，使用昨日已完成的税前总收益指数生成动量信号，按原始开盘价、10bps 滑点、原费率及上一日成交量 1% 上限生成真实模拟订单，再由 FIFO 账簿执行。收盘后才发放当日计划到账的分红，预留税款不能花掉。除息参考调整采用公告单独字段，未将股东每股现金直接冒充交易所参考调整。

账簿升级为 V2 的开盘、成交、收盘三个阶段；核对并保留原 V1 证据对应的 Git 提交 `790cd78`，没有用 V2 冒充旧账簿版本。旧研究原始成交内核及两条原实验结果仍能精确复现。V2 成本基础随 FIFO 剩余份额保存，用已获净分红权益计算持仓经济止损；8% 止损与永久回撤暂停、20% 单股/80% 总敞口上限不变。受阻卖单不能为新买单腾出虚假敞口额度。

新增输入前缀指纹和已知事件指纹，历史修订、参数路径或内核改变时拒绝续跑；支持 JSON 检查点恢复与增量/一次性一致。未知的未来事件不能通过新增周末计算点影响过去的风险峰值；非交易日支付可以单独推进，不能被遗漏或当作新交易日。期间绩效以该期间起始净值计算，累计收益单独标注。
