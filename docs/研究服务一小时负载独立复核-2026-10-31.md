# 固定一小时研究负载的独立复核（2026-10-31）

范围：内部研究、商业级质量。不是生产发布、实盘下单、策略晋级或盈利证明。

## 结果与边界

原 v1 注册协议的持续负载通过独立复核；整个计算进程组的内存容量仍未验收，商业级整体未完成。保留两种结论，不能把前者替代后者。

## 证据与复核

同一运行 `artifacts/quant-cpu-20261031/full-soak-1`，父进程真实 session 44868 最终退出 0，parent-exit 记录 worker 退出 0。计划 SHA256 为 `3f211f0089578dfb9b5d69c5109254a76f2ab19b99d97d8c71d6d26aa919ace1`，结果 SHA256 为 `40d56ccf5459276684e4a5fb668ea4011a95d1ed5fa6a62a2b7488bb29b4a616`。20 个源码字节留存于 full-soak-source-archive，复核只算摘要，不执行归档代码、不重放行情、不调用供应商。

`scripts/verify-quant-soak.py` 使用标准库只读 SQL（mode=ro、immutable、query_only），要求非空 WAL 单独冻结，不忽略它；校验父退出收据、计划/源码/原始输入、完整任务集合和实际终态。新增 16 项隔离测试覆盖虚假通过、缩短时长、丢失数据/结果、改写输入/源/耗时、活 PID、非空 WAL 和失败父进程。合成数据只在临时测试目录，不进入应用。

初次真实审计 full-soak-independent-review-1.json 因假设所有取消任务都有 dataset 而 KeyError，保留失败文件；40 个取消在封存前结束，没有 dataset 是合法终态。修复后既要求完成任务必须有原始数据，也要求取消任务已有的数据精确相等；正例含封存前/后取消，另有完成任务缺数据的拒绝测试。第二次 full-soak-independent-review-2.json 独立重算与生产者 v1 门槛完全相等。CLI 退出 2 是明确拒绝整体容量验收，不掩盖为返回 0；薄摘要见 quant-full-soak-review-20261031.json。

## 未关闭项

v1 `RUSAGE_SELF` 只记录 API 自身，不包括 CPU 计算子进程。143MB 不能当整组峰值；即使 v1 注册门槛通过，`internal_capacity_accepted`、`memory_scope_complete`、`production_SLO_certified`、`promotion_allowed`、`commercial_ready` 仍为 false。不能事后把缺少的度量补写为观测。

后续需单独登记覆盖计算进程及其后代的内存统计与退出核验，同样 4/2 并发、3600 秒、1GiB 门槛重测。先验证操作系统单位和峰值语义及短命子进程覆盖，不能靠降低并发、缩时、只采当前 PID 或重新解释旧协议补过关。

两组原策略仍未通过资格门槛，原来已见的 OOS/留出数据仍是开发数据，未提名挑战者、未开新模拟账户、未部署。这一小时证明的是指定本机单 API worker 的工程行为，不是收益增强、生产 SLO 或全站容量。
