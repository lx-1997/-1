# 旧账务档案升级保全与恢复v5验收

本轮修复已知v1账务档案在源码正常升级后阻断数据库备份的问题，不放宽策略或数学对账门槛。之前v4恢复调用“当前源码匹配”的档案验证器；这适合当前重放，却把旧档案的原始来源差异也当作备份失败。以实际9b4阶段双owner原实验档案复现：在正常引入独立存储校验器、保持当前重放仍严格匹配源码之后，原v4恢复明确报 `Historical source requires metadata/storage review, not current replay`，留下FAILED目录，原数据库主文件字节不变。没有伪造或修改这两份实际旧档案的来源标记。

新增独立 `quant_model_cost_integrity`，只校验已知 `qr-exact-model-archive-v1` 存储契约：原字节和结果指纹、原记录时钟、原源码清单、owner原快照关联、原实验/结果/数据/门槛关联，以及存储的模型版本/源码/检查点摘要和路径数量/日期关系。它按档案自身原来源校验，不要求原来源等于当前代码；不导入归档源码、不运行策略或成本模型，也不把历史记录中的“已验证”声明重新当成当前数学结论。未知结构、额外来源清单、重复键、非有限数、损坏、来源或owner错配仍拒绝。单原快照16MiB、单档案32MiB等已知存储边界保持。

当前重放验证器继续要求完整当前源码身份匹配。只读工作台对旧来源继续仅展示元信息，核验指标留空；没有迁移旧值、覆盖旧报告或把旧逐笔差异改成通过。当前版本入库仍实际重跑原实验、精确账务与持仓恢复，没有以存储校验替换这些数学步骤。

恢复协议独立升级为 `qr-quarantined-recovery-v5`，账务档案表改用存储/来源校验，并在收据和独立复核结果中明确记录：

- 支持的存储schema为v1；检查的是留存字节、owner输入和归档关系。
- 不要求留存来源等于当前来源，`mathematical_replay_performed=false`。
- 恢复副本保持隔离，`activation_authorized=false`。

独立复核拒绝把该范围修改为“执行过数学重放”；返回的范围对象也是副本，调用者修改返回值不会改变后续验证协议。v4历史证明和本轮首次失败完整保留，不重新标为v5通过。v5初次演练、后续响应对象隔离后的最终同版本源码收据按不同目录留存，以源码摘要区分，旧收据不覆盖。

实际旧库的最终验证：两份旧档案及原快照保全，原主文件SHA256保持 `5bc2e6b942e6359167ae4edf568e5d976193148a4fd3f409c6d8411b7ac3053e`。恢复副本的旧记录仅元信息可读，当前重放仍拒绝。密封隔离副本保持原样，再通过只读SQLite备份另建工作副本，在工作副本显式追加一份“升级后重新核验”记录；两份旧行所有字段均不变，owner原快照仍2条，档案变为3份。

新追加记录实际重算通过，并与旧档案的完整精确成本账簿、原策略门槛及旧严格对账值全等；旧资料仍保持旧身份，原策略均失败、旧账务差异仍0/2笔。新记录取得当前核验身份来自重新计算，不是把旧身份改名。最终对“仅旧档案”和“新旧混合”各执行全新隔离冷恢复，独立进程核验通过，恢复未运行数学模型、未激活交易。原始库、密封副本与工作库在各自只读验证阶段主文件字节保持，无模拟账户或生产写入。

新增14项隔离测试，加原档案/接口/恢复54项共68项定向通过。新测试覆盖历史来源的存储与只读元信息、当前重放拒绝、冷恢复无数学执行、9类损坏/未知结构拒绝、失败不生成READY、收据不能声称未做的数学重放，以及修改返回范围不污染后续验证。模拟来源失配只用于单元测试；上述实际旧库验证使用未修改的真实留存资料。
