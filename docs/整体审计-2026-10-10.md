**优先修复的问题**

**1．P1 流式 AI 问答先失败，再由前端兜底**

`POST /api/agents/tool-research/stream` 的外层创建 `hint`，内层 `run()` 又赋值同名变量，导致 Python 将其判为局部变量。普通问答在初始化前读取它，抛出 `UnboundLocalError`；圆桌分支同样受影响。前端收到错误后再发非流式请求，所以用户可能仍得到答案，但真实流式链路失效，并增加一次请求。

证据：[main.py:13440](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/main.py:13440)、[main.py:13455](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/main.py:13455)、[FinancialTerminal.tsx:2133](/Users/d-robotics/Desktop/超级智能体/-1-main/src/components/FinancialTerminal.tsx:2133)。提取真实 `run()` 后输入“根据文件看下茅台”，研究路由调用次数为 0，流返回 status 后返回未初始化变量错误。

修法：在 `run()` 开始设置 `run_hint = hint`，后续预取、圆桌和研究路由统一使用它。验收同时覆盖普通问题、大盘预取、附件和圆桌，并验证研究路由确实执行、最终返回 answer。

**2．P1 后端 AI 私有历史可跨用户读取**

`GET /api/dulus/memory?scope=user` 未进入只检查 `user:` 前缀的 owner 守卫；查询只过滤 `scope='user'`，会返回其他人的问题、答案和附件名。内存 SQLite 中分别放入 Alice、Bob 的假历史，原函数返回了两人记录。

证据：[main.py:11813](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/main.py:11813)、[dulus_runtime.py:125](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/dulus_runtime.py:125)。

修法：私有 owner 由服务端 JWT `sub` 决定，拒绝用客户端传入的裸 scope 选择全部用户；将 owner 从 tags 提升为独立字段。验收让两个用户互相读不到私有历史，并拒绝裸 `user`、伪造 owner 和匿名访问。

**3．P1 前端 AI 历史在同一浏览器串账号**

AI 历史使用不含账号的固定 localStorage key；登录后的服务器历史与原本地历史合并，登出也没有清空内存历史。A 提问后登出再登录 B，B 仍可看到 A 的问答。

证据：[FinancialTerminal.tsx:1822](/Users/d-robotics/Desktop/超级智能体/-1-main/src/components/FinancialTerminal.tsx:1822)、[FinancialTerminal.tsx:1887](/Users/d-robotics/Desktop/超级智能体/-1-main/src/components/FinancialTerminal.tsx:1887)、[FinancialTerminal.tsx:2988](/Users/d-robotics/Desktop/超级智能体/-1-main/src/components/FinancialTerminal.tsx:2988)。

修法：缓存按稳定 user ID 隔离；账号切换重置当前会话、历史、附件及在途请求。游客数据独立保存，旧全局缓存确认归属后再迁移。验收覆盖 A → 登出 → B → 刷新，以及 A 请求尚未完成时切到 B。

**4．P1 持仓、回测和通用 Agent 任务缺少对象权限**

这些表和接口未绑定 owner。临时库 TestClient 证实：Alice 创建持仓后，Bob 能在列表看到、修改、删除该持仓，均返回 200。回测与通用任务接口也没有 owner 查询条件，列表、详情、取消和重试存在相同结构问题。

证据：[risk_management.py:60](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/risk_management.py:60)、[main.py:14041](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/main.py:14041)、[main.py:14083](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/main.py:14083)、[main.py:11754](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/main.py:11754)。

修法：私人对象增加 `owner_user_id`，读写统一包含 `id AND owner_user_id` 条件。若某模块产品定义为共享演示，则明确区分共享与私人对象，限制共享数据的写权限。存量数据应先确认归属，避免默认分给某个账号。

**5．P1 改密码或设备退出后，旧 JWT 仍能访问部分接口**

全局 AuthMiddleware 只验证 JWT 签名与有效期；只有显式调用 `require_current_user` 的接口才验证当前会话。临时库复现：Alice 改密码后，同一旧 JWT 请求 `/api/auth/me` 返回 401，但查询、创建持仓仍返回 200。

证据：[auth.py:1160](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/auth.py:1160)、[auth.py:1199](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/auth.py:1199)。

修法：集中验证会话是否仍有效、账号是否存在且启用，路由统一复用此身份。权限校验遇到数据库异常应明确失败。验收覆盖改密码、设备挤下线、禁用和删除账号后的全部受保护接口。

**6．P1 匿名 AI 免费额度可被并发穿透**

代码先读取已完成次数，得到答案后才增加计数。同一 IP 在第一条请求结束前同时提交多条请求，都会通过额度检查。该行为由控制流确认，未用真实模型制造费用。

证据：[main.py:9254](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/main.py:9254)、[main.py:13124](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/main.py:13124)、[main.py:13230](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/main.py:13230)。

修法：在启动任务前用事务原子预占配额，成功提交、失败释放，并限制每用户或 IP 的在途任务数。额度账本独立于访问量统计；统计查询失败不能被当作零用量。验收并发提交多条请求，模型执行次数仍不超过允许额度。

**7．P1 回测盈亏和组合指标计算口径错误**

买入佣金只记日志没有扣现金；动量策略末笔平仓 PnL 的公式还把初始资金加了进去。原函数用本金 1000、价格 `[100,110,110,110]`、买卖佣金各 1%、零滑点，返回期末资金 990、平仓盈亏 **+990**。按现金同时支付买入费用的口径，正确期末资金为 **980.20**，净盈亏 **−19.80**。前端确实把此字段展示为“盈亏”。

证据：[backtest_executor.py:64](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/backtest_executor.py:64)、[backtest_executor.py:93](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/backtest_executor.py:93)、[BacktestCenter.tsx:558](/Users/d-robotics/Desktop/超级智能体/-1-main/src/components/BacktestCenter.tsx:558)。

组合曲线另外按“每跑完一个标的”追加终值变化，而非按交易日期合成净值；单标的最终组合指标只有初值与终值，无法反映中间回撤。证据：[backtest_executor.py:443](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/backtest_executor.py:443)、[backtest_executor.py:466](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/backtest_executor.py:466)。

修法：建立成交账本，统一现金、持仓成本与双边费用；各标的净值按日期对齐后相加，再算组合回撤和夏普。验收包括同价往返、先跌后涨、不同标的交易日期和现金守恒。

**8．P1 仓库 Docker 后端的干净镜像缺少启动依赖**

Dockerfile 只安装 `requirements-cloud.txt`，清单缺少 `passlib` 和 `SQLAlchemy`；`main → auth/storage` 又无条件导入这些包，干净环境会因缺少模块启动失败。本机已有依赖，无法用本机导入通过来证明镜像可启动。

证据：[Dockerfile.backend:13](/Users/d-robotics/Desktop/超级智能体/-1-main/deploy/Dockerfile.backend:13)、[requirements-cloud.txt](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/requirements-cloud.txt)、[auth.py:26](/Users/d-robotics/Desktop/超级智能体/-1-main/backend/deepfocus_api/auth.py:26)。

修法：维护一致的生产运行依赖清单，CI 在干净环境验证导入、启动与健康探针。

**9．P1 仓库 Docker 的数据库没有落到持久卷**

compose 只挂载 `/data`；账号和多个业务数据库的默认路径由 `__file__` 计算，实际位于容器 `/app`。把工作目录改为 `/data` 不能改变这些路径。使用默认配置重建容器会丢失未被持久化的账号与业务数据。

修法：统一数据根目录并让所有持久化模块从它解析路径；容器明确设置到挂载卷。验收先写入账号、历史和分享记录，重建容器后仍可读取。
