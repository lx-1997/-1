# 研报日期缓存报错与只读查询修复

已修复此前3项研报缓存路径共同报错：`_archive_report_date`使用了未定义的`_ARCHIVE_DATE_CACHE`和`_ARCHIVE_DATE_TTL`，在普通缓存解读、旧缓存键迁移及预热结果POST/SSE读取前抛NameError。相同3项失败已在改动前f178基线和新增身份检查的精确树分别复现，不通过删断言或跳过失败解决。

改用现有线程安全`ByteBoundedTTLCache`，正日期缓存有效期600秒，最多2048条、512KiB，单项不超过4096字节；缓存存日期字符串，TTL由单调时钟管理，不再手写墙钟时间戳元组。未知日期与查询失败不缓存，数据库暂忙时仍按未知日期处理，不改变会员或免费阅读规则。

日期元数据查询还从归档写连接拆为独立SQLite只读连接：URI `mode=ro`、连接超时2秒、`query_only=ON`，连接显式关闭。它不为只读查询创建缺失库，也不再通过写连接设置WAL。2秒是SQLite忙等待配置，不声称所有应用/磁盘故障都保证2秒完成。

新增6项回归覆盖预热日期优先、热缓存不再读库、600秒刷新、连接关闭、未知结果后可重试、模拟锁忙失败后可恢复且不放行、空ID、缺失库不创建及连接实际拒绝写入。它们与既有缓存/预热POST和SSE、通用缓存测试合计55项通过，原3项NameError路径不再失败；缓存命中场景明确不触发来源解析和模型生成。不能由这些隔离测试推断生产响应耗时或真实模型速度。

原量化/模拟盘门禁加本轮55项缓存相关检查在隔离Git精确源码副本运行，工具与7个客户端门禁也保留；实际数量和源码摘要在薄摘要及终态收据记录。整个backend先前仍存在其他已观察失败和中断，未宣称全仓通过，未用范围回归取代整体验收。

本轮仅改主服务中日期缓存/读取路径和新增回归，未改量化策略、成本、风险暂停、原实验或样本外门槛，没有生产部署。既有财报一小时是此前独立冻结源码的历史结论，不覆盖本轮主服务修改的容量。

证据：`artifacts/quant-report-date-cache-20261101/final/`；原失败对照保留在 `artifacts/quant-recovery-identity-20261101/baseline-cache-failure.log` 和 `current-cache-failure.log`。
