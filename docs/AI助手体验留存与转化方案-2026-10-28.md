# AI 助手体验、留存与付费转化 · 2026-10-28

目标：让用户更快完成一次有价值、可核对的研究，之后能回来继续；需要会员时能看清权益和实际价格。新增界面和埋点是待验证的产品假设，不能据此宣称留存或收入已经提升。

## 本次落实

| 目标 | 用户实际获得的改变 | 可观察信号 |
| --- | --- | --- |
| 降低首次提问门槛 | 自选用户看到“我的自选最近有什么变化”，选中后展示带名称/代码的可编辑问题；通用入口使用最近交易日，不写死“昨天” | ai_workspace_view、ai_starter、ai_request_start |
| 让研究有上下文 | 从文章阅读器进入助手，明确显示可移除的参考摘录；先编辑，再发送；SSE 与兜底请求带同一份上下文 | ai_context_open、ai_context_remove |
| 减少挫败 | 防重复提交，迟到事件无效；普通错误可重试原问题；停止也能中断深研降级请求；等待展示实际步骤，不承诺虚构的完成时间 | ai_answer_complete、ai_answer_error、ai_answer_stop、ai_retry |
| 建立回访路径 | 成功回答保存在当前账号的历史；新会话可以直接继续最近一次研究；不同文章的同问句不合并 | ai_resume、ai_followup、ai_answer_copy |
| 在明确需求处解释权益 | 额度/权限限制就地说明，保留问题；用户主动点击后直接打开真实套餐价格，避免额外一层促销弹窗；只有服务端标记可领取体验的账号才显示领取入口 | ai_access_gate、ai_login_click、ai_trial_click、ai_upgrade_click、open_buy |
| 不丢失已投入的工作 | 登录时把问题带回输入框；同账号领取体验导致认证版本变化后，仍恢复原问题与所选摘录 | 登录/体验领取后的草稿恢复测试 |

线上验收还修复了通用财务概念题被“不需要实时行情”等限定语误送实时取数的路由；仅对严格术语解释生效，具体公司与最新数据仍取证。

默认回答请求偏向“结论、依据、主要风险”；明确要求详细分析时保留详细模式。模型与取数结果具有不确定性，不能把提示词修改等同于每次都能产生高质量短答。资料摘录会明确标注覆盖限制；实际研究警告在深研正文外直接可见。

## 如何判断是否有效

先排除站长、验收账号、内部测试与机器人。账号口径使用稳定 account id，匿名会话只用于获客入口，不能与登录用户混算留存。

1. **体验**：回答完成率 = 完成回答次数 / 发起研究次数；同时看停止率、错误率、重试后成功率，以及完成耗时 P50/P90。普通与深研分开统计，降级只算同一次尝试的一个最终结果。
2. **激活**：首次获得成功回答的新用户数；点击“AI”或发送过问题不等于激活。可以再看其中有追问、复制或下一次回看的用户数。
3. **留存**：以首次成功回答的北京日期建 cohort，计算 D1/D7 再次成功完成研究的比例。未到观察日的 cohort 不进分母，同时展示样本数；需要结合全站原有 cohort 快照，防 activity_log 滚动裁剪造成误判。
4. **转化**：查看权益 → 打开套餐 → 真实支付确认 → 权益到账。ai_upgrade_click/open_buy/buy_paid_click 只能说明意向；不能把“我已付款”的点击、赠送会员或领取体验当成真实收入。本次没有增加支付订单账本，实付转化仍须与可靠支付/开通记录核对。
5. **付费后的体验**：付费用户仍应保持回答完成率，并持续回来完成研究。转化提升同时伴随错误率或退款上升，不算成功。

先观察上线后的真实用户路径与样本量，再选择是否调整首问体验额度、套餐或权益。现有可领取体验入口优先用好；本次不改变服务端资格、次数、价格、自动续费或支付条件，也不自动订阅推送。

## 后续优先级

- 先解决真实用户最常失败的取数与回答路径，并检查答案引用与风险披露。
- 按用户主动关注的股票，支持“较上次研究有哪些变化”；提醒应由用户主动开启，有明显变化才通知。
- 在成功研究之后说明会员能持续提供的价值，避免在空白欢迎页堆促销。
- 若大量用户在支付与开通之间流失，再优化支付确认和到账链路；不要用新增弹窗代替修复真实阻力。
