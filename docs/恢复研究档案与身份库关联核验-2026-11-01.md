# 恢复研究档案与身份库关联核验

新增独立只读检查，补上原v6恢复流程未覆盖的“研究档案owner是否仍在指定身份快照中”的核验。它不修改v6源码身份、旧READY链、研究所有权或账号状态，也不允许激活服务。

## 检查范围与拒绝规则

先重新通过既有v6研究副本验证，再遍历已支持表的owner。账号查询只投影原始id与is_active，不按用户名/邮箱找替代身份，不输出账号ID、密码、联系方式或会话。报告给出所有者数量、缺失和停用数量及各研究表记录数。空档案不能冒称已验证账号关联；未知研究表、无效/歧义账号状态、超过200字符的原始owner或超过10000个owner均拒绝。超长owner在SQL层先拒绝，避免分组结果将大段字段载入Python。长查询有进度预算。

只接受显式绝对路径的、无WAL/回滚日志的DELETE模式冷副本。两个数据库分别持有只读事务并核对读取前后main摘要；这不会制造跨数据库原子快照，不能把两个只读事务说成一个全局事务。模块加载时固定源码摘要，运行前后再次验证，加载后的文件变化会拒绝。

`correspondence_check_passed=true`只表示档案中确有owner、其精确ID都存在且is_active标记均为1；它不表示密码有效、能完成登录、会员/角色权限正确或历史身份未被恶意替换。`identity_continuity_verified`、`atomic_cross_database_backup_verified`、`JWT_and_sessions_restored`和`activation_authorized`始终为false。停用身份仍保留在档案中，检查退出2，不自动重新启用或删除记录。

## 已执行的真实隔离数据案例

使用此前已停止的financial-workspace qa-v3环境保留的研究库与同一环境身份库，先确认旧端口关闭；新建研究隔离恢复副本及SQLite backup身份快照，目标在第一次只读查询前转换DELETE并关闭连接。保留原QA生成的真实ID，本轮没有再映射owner或重建同名身份冒充原账号。

| 身份副本 | 结果 | 退出码 |
|---|---|---:|
| 原QA身份ID、active标记保留 | 关联通过 | 0 |
| 独立副本删除对应身份 | 缺失1个，拒绝 | 2 |
| 独立副本将对应身份停用 | 停用1个，拒绝 | 2 |
| 独立副本更换ID、用户名保留为原ID | 原ID缺失1个，拒绝同名替代 | 2 |

这批档案含1个财报父回执、2个提取及10份原文BLOB。原QA两个main文件前后摘要不变，所有案例的研究副本和指定身份副本均只读。原始/中间版结果和失败报告都保留；最新源码结果在 `artifacts/quant-recovery-identity-20261101/current-v2/`。这是停止的自有QA环境案例，不是生产跨库恢复或真实业务身份连续性认证。

操作入口：

```sh
backend/.venv/bin/python scripts/quant-recovery-identity.py \
  --workspace /absolute/quarantined-research-workspace \
  --auth-snapshot /absolute/closed-auth-snapshot.sqlite3 \
  --output /absolute/new-owner-correspondence-report.json
```

输出必须是新文件；校验失败也保存明确拒绝报告并退出2，不覆盖旧结果。此命令不创建身份快照、不接受活动身份库、不改密钥或轮换会话。

## 回归范围与新发现的整体验收缺口

本轮曾扩大执行整个backend测试，实际出现16项失败，2995项通过、22项跳过；后续研究流长时间未结束，主动中断自有pytest，退出2并保留完整日志。失败包括缺少EdgarTools/qlib、研报缓存引用未定义`_ARCHIVE_DATE_CACHE`、会员前置和预热测试不一致。没有安装依赖、放宽断言或把这次中断说成全仓通过。

其中3项研报缓存失败已在改动前提交 `f1786d7ebda477f281c13062d96cde27509083c4` 的独立导出和新增检查的精确树上分别重现，失败节点一致；其余全仓失败尚未逐项完成基线分类，仍是整体商业级验收的开放缺口。旧“1491项后端”门禁的准确范围是量化/模拟盘测试加三个相关接口文件，并非所有backend测试。本轮继续按相同范围执行，不由该范围通过推断全仓绿色。源码指纹、实际案例及最终门禁收据另留薄摘要。
