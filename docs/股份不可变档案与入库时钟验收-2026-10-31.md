# 股份不可变档案与入库时钟验收（2026-10-31）

为内部研究接通股份原文、数量计划和复核结果的持久化与冷恢复。不是券商账户认证、现金/税基/NAV统一交易，也不授权模拟晋级或实盘。本次新增数据库收据，不改原两组价格实验、股票池或门槛。

## 存储与可用时间

`quant_share_store.py` 在同一QR库添加qr_share_source、qr_share_bundle、qr_share_review三张表。原文、声明、系统入库时钟及数量复核结果均按owner过滤；普通SQL更新/删除被不可变触发器拒绝。操作员入口可信，owner作用域校验不替代将来HTTP鉴权；原文摘要也不是外部签名或券商内容自动认证。

系统在BEGIN IMMEDIATE拿到写锁后才取recorded_at，并以其后一个北京时间自然日零点作为stored_visible_at。调用者没有覆盖此时间的参数。原available_at/observed_at声明保留在input，不把早期公告日期当本系统早已存储的证据；重复输入返回原收据及原记录时间。

公告事实、账户登记快照和获配确认分别保存首次收据引用。后来补确认时，已存的相同公告事实和快照保留旧时间，新确认从自己的边界开始可用；不能只凭PDF早已存在就把后来提取的不同事实或新持仓快照倒填。重采相同事实也不抹去较早记录：实存模式的派生计划使用各部分首次系统可用时间，输入声明仍完整留存；获配的派生事件指纹随之明确绑定，未修改原文。

as_recorded要求登记阶段已知公告与快照，入账阶段已知获配。未满足时保存not_available_as_recorded结论，不假装无分红或无持仓；historical_reconstruction另行标注，可以做假设重建，不能冒充当时系统已知。未来复核视点拒绝。不同输入复用同一复核key也拒绝；零碎缺确认保存awaiting_allotment及待收状态，区别于无效输入。

库存、公告事实及同一获配标识出现冲突时，拒绝静默覆盖；当前不提供事实修订迁移。资料每包25MiB、单PDF10MiB，账户原文100MiB、元数据50MiB、结果100MiB和数量限制；组件全局逻辑存储512MiB。UTF8元数据按字节计算，不以SQLite字符数低估用量。这些是组件额度，不是已验证的全站磁盘SLO。

## 可操作入口与恢复

`scripts/quant-share-receipt.py --db <绝对QR路径> --owner <内部目标> import --plan <绝对计划> --label <标签>`导入现有数量计划与原文。inspect只读查看指定收据；review要求显式id/key/as-of/mode和全新输出路径，复核记录不可变落库。退出0的数量复核仍只是quantity_model_completed，不能交易；资料不可用或待获配返回2，同时保留审查记录与报告。原来的独立数量CLI也明确返回awaiting_allotment，不再把合法待决与畸形输入混称。

恢复升级为qr-quarantined-recovery-v3，包含全部三张新表及来源关系。独立新进程只读核对输入/原文/收据、重算已归档的纯数量结果并比较；不启动任务、交易或归档代码。源库不写，恢复副本依旧隔离且activation_authorized=false。旧v2恢复收据和源码身份保留，不用v3重新宣称旧证明有效，也不自动迁移旧股份检查点。
